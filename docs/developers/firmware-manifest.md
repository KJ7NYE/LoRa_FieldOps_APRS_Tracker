# Firmware update manifest (`firmware_manifest.json`)

Machine-readable description of a release's firmware images, so the FieldOps
app can find, download, verify and install the right image over Bluetooth.
Generated by `tools/generate_manifests.py` in the `publish-manifests` job of
`.github/workflows/flasher.yml` on every published release.

## Where to fetch it

| URL | Use |
|---|---|
| `https://raw.githubusercontent.com/KJ7NYE/LoRa_FieldOps_APRS_Tracker/main/flasher/manifests/firmware_manifest.json` | **Latest release.** Stable URL, CORS-enabled, ~5 min edge cache. |
| `https://github.com/KJ7NYE/LoRa_FieldOps_APRS_Tracker/releases/download/<tag>/firmware_manifest.json` | A specific release (asset attached to each release). |

The first release that carries this file is the first one after
`feat/firmware-manifest` is merged. Earlier releases have no manifest.

## Schema (version 1)

```jsonc
{
  "schema": 1,                       // incompatible changes bump this; refuse unknown values
  "version": "v1.4.8",               // release tag (same format as `version.date`)
  "published": "2026-11-23",         // UTC date the manifest was generated
  "repo": "KJ7NYE/LoRa_FieldOps_APRS_Tracker",
  "release_url": "https://github.com/KJ7NYE/LoRa_FieldOps_APRS_Tracker/releases/tag/v1.4.8",
  "boards": {
    "<board id>": {                  // = the tracker's `version.board` (PlatformIO env name)
      "label": "Heltec WiFi LoRa 32 V3.2",
      "chip": "ESP32-S3",            // ESP32 | ESP32-S3 | nRF52840
      "image": {
        "file": "heltec_v3_433_aprs_firmware.bin",
        "url": "https://raw.githubusercontent.com/.../flasher/firmware/heltec_v3_433_aprs_firmware.bin",
        "release_asset_url": "https://github.com/.../releases/download/v1.4.8/heltec_v3_433_aprs_firmware.bin",
        "size": 1614864,             // bytes
        "sha256": "b9648d85…"        // lowercase hex of the whole file
      },
      "ble_update": { … } | null,    // see below; null = no Bluetooth update for this board
      "ble_update_unavailable_reason": "…"   // present only when ble_update is null
    }
  }
}
```

### `ble_update` variants

**ESP32 dual-slot boards**: the GATT protocol in `include/ble_ota.h`:

```json
{ "method": "esp32_ble_ota", "protocol": 1 }
```

`protocol` is the value to send in START (and the one READY must echo). Send
`image.size` and `image.sha256` (as 32 raw bytes) in START, and the board id in
START's board field.

**Heltec T114**: Nordic legacy DFU through the Adafruit bootloader, image is
the DFU zip:

```json
{
  "method": "nordic_legacy_dfu",
  "packet_receipt_notification": 6,
  "max_packet_receipt_notification": 8,
  "keep_bond": true,
  "refresh_gatt_cache_after_jump": true
}
```

The fields encode the rules in `docs/developers/ble-ota-plan.md` ("T114 DFU
rules"): PRN at most 8 (6 recommended), keep the bond, and refresh the GATT
cache after the buttonless jump before starting the DFU library.

**Single-slot ESP32 boards** (`tbeam_433_aprs`, `lilygo_t3_433_aprs`):
`"ble_update": null` with a user-facing `ble_update_unavailable_reason`.
The image is still listed (it's the web UI / USB update file).

## Rules for clients

- Look the board up by `version.board`. A board missing from `boards` means its
  build failed for this release (the generator skips missing files and logs
  a warning): tell the user no update is available.
- Offer an update when `version` is newer than the tracker's `version.date`,
  compared on major.minor.patch (`FirmwareVersion.parse` in the app). Dev
  builds (`v1.4.7-6-g…`) compare by their tag prefix.
- **Always** check the downloaded file's size and SHA-256 against `image`
  before sending it to the tracker; discard it on mismatch.
- Unknown `method` values: treat as "update not supported by this app version".
- Fields may be added within schema 1; ignore unknown keys.
- Whether the *tracker* offers the update service is still decided at runtime
  by GATT service presence (it also needs *Require PIN* on). The manifest says
  what the board can do with a current firmware; the GATT table says what the
  connected tracker can do right now.
